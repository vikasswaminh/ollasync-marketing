### Real-Time Infrastructure (WebRTC) vs. Chunked Asynchronous Delivery (HLS/CMAF)

Synchronous webinar and meeting platforms run almost entirely on WebRTC via Selective Forwarding Units (SFUs). 

* **The WebRTC SFU Model:** Every participant sends an upstream media track via UDP. The SFU unpacks, decrypts, and redistributes these packets to every subscriber in the room. This process requires persistent, stateful cloud server instances running at peak capacity for the entire duration of the call. If 500 people join a live all-hands, the infrastructure must ingest, route, and deliver 500 parallel streams concurrently.
* **The Asynchronous Ingestion Model:** Asynchronous workflows decouple recording from distribution. Video is recorded locally via MediaStream Recording APIs or captured via desktop pipelines, compressed client-side, and ingested as discrete chunks into cloud object storage (e.g., AWS S3, Cloudflare R2). 

Once ingested, modern async video uses standard chunked HTTP Live Streaming (HLS) or Common Media Application Format (CMAF). The assets are distributed over edge CDNs rather than routed through stateful media servers. The cost differences are massive: serving 10,000 global viewers via cached CDN edge nodes costs a fraction of maintaining a 10,000-seat live WebRTC SFU cluster.

### The Translation Bottleneck: Real-Time Compute vs. Decoupled Inference

Global teams run into their hardest engineering constraints when introducing multi-language localization. 

#### Synchronous Translation
Providing live translation inside platforms like Zoom or ON24 requires one of two options:
1. **Human Interpreters:** Adding secondary audio channels manned by human translators at $150–$300/hour per language.
2. **Sub-Second Streaming ASR:** Running automatic speech recognition (ASR) models with sub-second lookahead windows. These models consistently sacrifice contextual accuracy to hit latency targets under 800ms. If the speaker uses domain-specific jargon or complex syntax, early tokens translate incorrectly before the sentence completes.

#### Asynchronous Translation
Async media pipelines run transcription and translation as an asynchronous batch or nearline inference task. When a recording finishes:
1. The raw audio track routes to a transformer-based speech recognition model.
2. The entire context window of a sentence is ingested before running translation, eliminating the misinterpretations common to real-time predictive text.
3. The pipeline generates target-language subtitles, synthetic voice-dubbed audio tracks, and localized transcripts simultaneously.

This explains how asynchronous video is solving the enterprise localization problem without requiring six-figure translation budgets.

#### Step 1: Establish Strict Meeting Triage
Enforce a baseline rule: **No updates in real time.**
* **Live (Sync):** High-stakes conflict resolution, bilateral negotiations, direct personnel reviews, brainstorming sessions with fewer than four participants.

Engineers and product managers avoid async video when it requires production overhead. Remove the friction:
* Cap routine async updates at five minutes.
* Ban script editing and studio setups for internal comms.
* Mandate the **Context-Action-Result (CAR)** framework:
  * **0:00–0:45:** The problem or objective.
  * **0:45–3:30:** Screen share walkthrough of the work.
  * **3:30–5:00:** Next steps, ownership assignments, and required feedback.

#### Step 3: Centralize the Feedback SLA
Async communication fails when updates drift into an unanswered void. Treat async video consumption like a service level agreement (SLA):
* Viewers must acknowledge or counter within 24 hours (or across one local business day).
* Feedback must be time-stamped directly on the video or left in a centralized, text-based thread.
* If no objections are logged within the SLA window, silent consent is assumed, and the project moves forward.

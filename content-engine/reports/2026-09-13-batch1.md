# Content engine — initial execution report (batch 1 dry run, 2026-09-13)

Policy: `ollasync_seo_content_engine_master_policy` v1.0 ([policy.json](../policy.json)). Scope as instructed by the
operator during the build: **static site only** (nothing on the backend or the VM), model access through the engine's
own OpenRouter call with the operator's gateway first when configured, runs **on demand from the operator's
workstation** (no unattended scheduler), publication **by pull request only**.

## 1. Architecture used
A dependency-free Node engine in `marketing-site/content-engine/` (`engine/*.mjs`, 10 modules, ~1,600 lines): manifest
state machine → cannibalization check (TF-IDF + model intent check) → product facts → live-checked competitor claims →
brief → writer (temperature 0.45) → human-editor pass (a different model) → deterministic gates → independent review
(different model, the policy's nine weighted dimensions + eleven questions + claim mapping) → at most one repair pass →
originality check → draft file (dry run) or `src/content/blog/<slug>.md` (`--publish pr`) → run record. Every stage
persists to `work/<id>/` so an interrupted run resumes without paying twice; `.lock` prevents overlap; five attempts
per Asia/Kolkata day across all runs; blocked drafts are kept as `drafts/blocked-<slug>.md`.

## 2. Existing components reused
The blog collection and `BlogPost.astro` layout (BlogPosting + BreadcrumbList JSON-LD, canonical, sitemap), the site's
data files as the fact substrate, `scripts/mkt_no_leak.sh` (its patterns are parsed at run time — one banned-name list),
the three deploy gates plus the new SEO audit, `scripts/indexnow_ping.mjs`, the pinned-host / reasoning-off request
shape of the app's AI-notes OpenRouter call (mirrored, with a test that both send the same protective fields), the
operator's ollima gateway (same endpoint and thinking-off fields as the app). The backend was not modified.

## 5. Scheduler configuration
None installed, by the operator's decision. The README documents the slot for whenever one is wanted: `30 4 * * *`
UTC = 10:00 Asia/Kolkata (no DST), or a Windows Task Scheduler entry; `test/schedule_and_crawl.test.mjs` verifies the
documented line converts to 10:00 IST. The engine itself is idempotent, locked, resumable and capped at five
attempts per day, so a scheduler can call it blindly.

## 6. Models configured (all through `OPENROUTER_*` / `LLM_GATEWAY_*` environment, nothing hard-coded twice)

|---|---|---|---|

Preflight refused nothing in the accepted runs; the ceiling test proves `google/gemini-3.1-flash-lite` ($1.50/M
output) is refused. Provider allow-list: the app's `CoreWeave, Parasail, DeepInfra, Google AI Studio, Google, OpenAI`.

**Model findings from the dry run (the reason the accepted runs did not use the policy default):**
- Gateway `deepseek-v4-flash`: spent the whole 5,000-token output cap and returned a cut envelope, or empty content —
  never a usable article. The engine now treats a `finish_reason=length` or empty reply as a model failure and moves on.
- Gateway `glm-5.2`: wrote a good 2,522-word article in 38 s twice, then returned empty on the next attempts (about
  60 s lost per empty reply); every repair call returned empty. Usable as an optional free writer, not reliable.
- OpenRouter `google/gemini-2.5-flash-lite` (policy default): ignored the structural checklist even in the repair pass
  (fact ids in the prose, 25-word answers under question headings, insight headings that no longer matched) — one
  sample; kept as the code default, not recommended until re-tested.
- OpenRouter `deepseek/deepseek-v4-flash-0731` writer + `qwen/qwen3-32b` reviewer: the configuration that produced the
  batch-1 results below. Recommended environment for the next batches (`OPENROUTER_MODEL_CONTENT=deepseek/deepseek-v4-flash-0731,google/gemini-2.5-flash-lite`, `OPENROUTER_MODEL_CONTENT_REVIEW=qwen/qwen3-32b,nvidia/nemotron-3.5-lightning` — the two lists must not share a model, so a fallback can never review its own draft).

## 7. Cost-control implementation
Output-price ceiling ($1/M) checked against OpenRouter's public model list before the first call and again on the
served model after every call; writer ≠ reviewer enforced; per-article cap ($0.25, 60k tokens), per-run cap ($1.50,
150 min); five attempts per IST day across runs; a truncated or empty reply never counts as a draft; one repair pass;
blocked items are never retried unless asked (`--retry`); `--rejudge` re-applies tuned gates to a stored draft with no
model call; the ledger records model/provider/tokens/cost/latency/status per call and per stage.

## 8. Quality-gate implementation
Deterministic (`engine/gates.mjs`, 40+ checks): one H1 (from the title, none in the body), heading hierarchy, 900–2,600
words, intro ≤ 180 words, 1–3 question headings with a 30–125-word standalone answer, no repeated question across
articles (registry), pillar link, canonical link form, ≤ 8 internal links, broken links, descriptive anchors, external
links only to stored sources, no images/embeds/HTML, forbidden phrases (from the policy), the site's no-leak patterns,
invented-claim patterns (certifications, EU/self-hosting, customers, latency, statistics, language counts — negation
aware), placeholders and truncation, keyword stuffing, ≥ 2 insight sections citing real fact ids (writer + reviewer,
tolerant heading match), comparison fairness section, cadence (section openers, filler openers, bullets, three-item
lists, em dashes, bold, sentence rhythm). Model review: nine weighted dimensions, eleven questions, every Ollasync /
competitor / number claim mapped to a fact or source id; ≥ 85 approve, 75–84 one repair, < 75 block; block after a
failed repair. Originality: TF-IDF cosine ≥ 0.82 blocks against every built page, every planned topic and the run's
other drafts. Publication path: an approved article is a draft file until promoted; the four site gates run on deploy.

## 9. Human-editor implementation
Two layers. The policy's editor pass is a model stage (the reviewer model, allowed to cut 20–30 %, merge, reorder,
rewrite the intro, never add material, never below 1,200 words). The last gate is a human read before promotion:
`--block <id> --reason "…"` records an editorial block, and a draft in `drafts/` is a reviewable file in the PR.

## 10. Cannibalization protection
Before any draft is paid for: the item's brief is compared (TF-IDF over title + queries + angle) with every built page,
every manifest topic and the run's approved drafts; the nearest three get a model intent check ("would the searcher be
fully served by that page?"); same intent → blocked with the page to expand. Manifest creation pre-blocked one known
duplicate. After writing: the full text is compared again (≥ 0.82 blocks). Calibration on batch 1: brief-vs-page
scores were 0.04–0.16 (true neighbours included), which is why the intent-check trigger is now 0.05 rather than 0.28.

## 11. OAI-SearchBot status
`robots.txt` allows every agent (no GPTBot line was added or changed). Live test 2026-09-13 (`CRAWL=1`): OAI-SearchBot
and Googlebot both fetched `/blog/how-live-voice-translation-works-in-class/` with HTTP 200 and the article text and
BlogPosting JSON-LD present in the HTML. Articles are static HTML; nothing renders client-side.

## 12. Technical SEO status
Every built page: title, description, self canonical (trailing-slash form), unique titles and descriptions site-wide;
every post: one H1, `<article>`, BlogPosting whose headline/description/dates/mainEntityOfPage/author match the visible
page, BreadcrumbList ending in the H1, ≥ 300 words of article text in the HTML, sitemap membership; drafts never
built or listed; per-post `lastmod` from `updatedDate ?? pubDate` (26 posts now carry their own dates). Enforced by
`scripts/mkt_seo_audit.mjs` as deploy gate 4 and a CI step (83 pages / 26 posts pass today).

## 14. Estimated cost per article
≈ $0.004 with the deepseek writer and the qwen reviewer (≈ 25k input + 11k output tokens including the editor pass,
review, one repair and a second review); ≈ $0.006 with the policy's gemini default; ≈ $0.0025 when the gateway
serves the writer (reviewer/editor only). Wall time ≈ 3 minutes per article on OpenRouter.

## 15. Estimated cost for all 50 articles
≈ $0.20 at the measured average, ≈ $0.30–0.40 allowing for retries of blocked items; the whole dry run including its
debugging iterations moved the OpenRouter key's lifetime usage from $0.116 to $0.162 ($0.046).

## 17. Remaining risks
- The reviewer (qwen3-32b) passed two invented-mechanism statements; the deterministic gates cannot catch those. A human
  read before promotion stays mandatory; the prompt change targets exactly that class of statement.
- Long-answer and related-link thresholds were tuned on this batch; expect further tuning in batches 2–3.
- The gateway writer is free but flaky (empty replies); OpenRouter is the reliable path at cents per article.
- Competitor claims exist for Zoom, Google Meet, Teams and BigBlueButton (10 quotes) and are re-verified on every use;
  batches 4–6 will need more claims as their briefs demand them.
- Search Console is still not verified (open since 2026-08-31): the analytics loop has no data. Conversions and
  AI-referral traffic cannot be attributed with the edge page-view analytics the site has.
- Existing content defects outside the engine's scope, for the operator's decision: 33 old links to the 301'd
  `/self-hosted`, three links to CamelCase slugs (404), the healthcare page's "the data stays in the EU" sentence.

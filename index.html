How it works

The server holds ciphertext. Only the room holds keys.

Identity and media keys are generated and kept in your browser — each room's key is shared only through the invite link, never with our servers. Message, call and screen-share frames are all sealed with it. The delivery service and the SFU relay encrypted bytes they cannot read — verified end-to-end, not asserted in a policy doc.

Security

The server holds ciphertext. Only the room holds keys.

Verified end-to-end encryption, not asserted in a policy doc. Here is exactly what we can and cannot see.

What the server never sees

  • ✓ Audio, video and screen-share content
  • ✓ Chat messages and shared files
  • ✓ Room encryption keys
  • ✓ Deal-room documents

What the server does handle

  • • Encrypted byte relay between peers
  • • Auth & session tokens (SSO / passkeys)
  • • Room membership & routing
  • • Tamper-evident audit metadata

Quickstart

Create an encrypted room and invite a peer. The room key is generated in the browser and shared only through the invite link — it never reaches our servers.

room.ts
// keys are generated client-side, never sent to the server
import { createRoom } from "@ollasync/sdk";

const room = await createRoom({ e2ee: true });
console.log(room.inviteLink); // share this out-of-band

await room.join({ camera: true, mic: true });
